# Click613 WhatsApp bot: grocery price comparison (+ eruv feed)

For Chanoch. Everything runs on our side; the bot makes **one HTTP call per incoming message** and sends back the text it gets.

Spec page (phone-friendly): https://click613grocery-api.sites.tab.bot/

## 1. What it does
People text the Click613 bot and get kosher grocery prices compared across stores in their area:
- **Price of an item**: "price of tuna", "how much is Heinz ketchup", a barcode
- **Another area once**: "cheapest eggs in Monsey"
- **A shopping list**: several lines (one item per line, "2 milk" or "milk x2" for quantities) → cheapest store per item, best single store for the whole list, cheapest total across stores
- **Sales**: "sales this week", "sales at Seasons"
- **Area**: asked once, remembered ("area Monsey" changes it)

Areas: Lakewood, Brooklyn: Boro Park & Flatbush, Brooklyn: Williamsburg, Five Towns, Monsey, KJ / Monroe, Teaneck.
Each item reply also carries, where we have it: the **big-chain line** (Walmart, Amazon… same product and size), **≈ approx. stores** (stores with no price website, e.g. Bingo, estimated from Instacart prices with the markup removed, always marked "≈ … (approx.)", never counted in list totals), a **"Cheaper kosher option"** line with a link (OU-confirmed pareve store-brand item at Aldi/Lidl/Amazon), the **read date** and "Confirm in store", and a link to the full price page.

## 2. Integration: one call
`POST https://click613grocery-api.sites.tab.bot/api/v1/reply`
```json
{ "text": "<the user's message>", "state": <the state you saved for this phone, or {}>, "force": false }
```
Answer:
```json
{ "handled": true, "reply": "<WhatsApp text to send>", "state": {...save this per phone...}, "kind": "item|list|sales|ask_city|city_set|closest|no_match|help|hint" }
```
- `handled: false` → not a grocery message: carry on with your other handlers (eruv, jobs, morah list, menu…). Still save `state`.
- `state` is a small JSON object (area, the last "reply 1/2/3" choices, a timestamp). Store it per phone number and send it back unchanged. Nothing else to keep.
- `force: true` when the user is inside a "Grocery prices" menu option of yours (then any text is treated as an item).
- Recognised without a menu: messages starting with price/prices/cost/how much/cheapest/compare/grocery/shopping list/list/sales/deals, any multi-line message (a list), "area <name>", and, for 20 minutes after a grocery reply, a plain item name ("heinz ketchup") or a number answering "reply 2 or 3". Chat like "thanks"/"yes" is not taken.
- Oct 25 2026: also recognised: a price word anywhere in the message ("where is milk cheapest in Lakewood", "milk price lakewood", "compare egg prices", "how much is tuna in Far Rockaway"), answered only when an item matches (otherwise handled:false so the bot carries on). No area named and none saved → Lakewood (not saved; the reply says how to ask for another area). Item replies are short: "✅ Cheapest: <store> $<price> · updated <date>", then "Also: …" for up to 4 other stores. `data.cheapest` = {store, price, read, only_store}.
- "menu", "exit", "stop", "0" return `handled: false` (your menu takes over).
- Timeout: answers come back in well under a second; use an 8 s timeout and treat errors as `handled: false`. Send any normal User-Agent (Python's bare urllib default is refused by the edge; `requests`, Node fetch and axios are fine).
- Drop-in code: https://click613grocery-api.sites.tab.bot/reference/click613-grocery.js (Node) and https://click613grocery-api.sites.tab.bot/reference/click613_grocery.py (Python).

## 3. Reply formats (exact, generated by the API)
Rules built in: short WhatsApp text with *bold*; no item counts anywhere; approx. prices marked "≈" and "(approx.)"; Amazon marked "price varies, may include shipping"; read date on every reply plus "Confirm in store"; data older than 14 days says "⚠️ Older read (date): prices may have changed."

```

≈ Bingo  $3.59 (approx. cheapest)
1. Nutmeg  $3.89 ✅ cheapest
2. Aisle 9  $3.99
3. Aisle 9 Jackson  $3.99
4. Kosher West  $3.99
5. Kosher Village  $4.09
Cheaper kosher option: Lidl Crushed tomatoes 28 oz. $1.55 (60% less per oz, OU Pareve) https://www.lidl.com/p/crushed-tomatoes/p11237331
≈ Bingo has no price website: estimated from its Instacart prices with Instacart's 17.5% markup removed, read Oct 18.
Store websites, read Oct 16. Confirm in store.
More: https://lakewoodprices.sites.tab.bot/?q=Lieber's%20Crushed%20Tomatoes
```
When there are other close matches, the item reply ends with (example: "heinz ketchup"):
```
Not this one? Reply a number:
2. Heinz Tomato Ketchup, 14 Oz (from $3.29)
3. Heinz Tomato Ketchup, 64 Oz (from $9.99)
```

## 4. Other endpoints (JSON, if you want to build your own wording)
- `GET https://click613grocery-api.sites.tab.bot/api/v1/search?city=monsey&q=eggs&limit=3` → items with every store price, approx flag, sale/was, deal, link, read date, stale flag, big chains, cheaper kosher option; plus `whatsapp_text`
- `POST https://click613grocery-api.sites.tab.bot/api/v1/list` `{"city":"lakewood","items":["eggs","2 milk"]}` → per-item cheapest, totals per store (approx. stores excluded and named in `approx_excluded`), `whatsapp_text`
- `GET https://click613grocery-api.sites.tab.bot/api/v1/sales?city=lakewood[&store=seasons]`
- `GET https://click613grocery-api.sites.tab.bot/api/v1/cities` → area keys, names, stores (approx. ones marked), read dates
- Raw data files (if you want to cache on your side, max ~1 h; CORS open): `https://click613grocery-api.sites.tab.bot/api/v1/data/cities.json`, `https://click613grocery-api.sites.tab.bot/api/v1/data/<city>/index.json`, `https://click613grocery-api.sites.tab.bot/api/v1/data/<city>/sales.json`
City keys: lakewood, boropark, williamsburg, fivetowns, monsey, kj, teaneck (names like "Boro Park", "Five Towns", "Monroe" also work).

## 5. Data and refresh
Prices come from each store's own website (approx. stores: one Instacart read with the markup removed). The API files are rebuilt from the city price sites; Lakewood updates every morning (~5 AM ET), the other areas when we refresh them. The live endpoints always read the newest files, so nothing to refresh on your side. If you cache the static JSON, keep it ≤ 1 hour.

## 6. Eruv (live data for click613.com/eruv and the bot)
- The live eruv map is https://eruvin613.sites.tab.bot/ — every change is made there first.
- Plain GeoJSON of all eruvin (boundaries, lines and approximate pins, with hotline, contacts, auspices): **https://click613grocery-api.sites.tab.bot/api/v1/eruv.geojson** (CORS open, so click613.com pages can load it directly) — republished by us every time the map changes.
- Lookup for the bot: `GET https://click613grocery-api.sites.tab.bot/api/v1/eruv?lat=40.096&lng=-74.217` → `inside`, `may_cover`, `whatsapp_text`. Use it when a user shares a WhatsApp location:
```
📍 Inside the drawn boundary of:
• *Princeton Monmouth Eruv – Sections A & B*
  Check it's up: (732) 234-9837 (to verify the eruv is up) · text @mnmth-eruv to 81010
Always check the eruv is up before Shabbos and ask your Rav. Map: https://click613.com/eruv
```
  It never says "outside an eruv"; with no drawn boundary at the spot it says so and lists eruvin that may still cover it.
- Please have **both click613.com/eruv and the bot pull the GeoJSON URL automatically** (cache ≤ 1 hour) instead of the old snapshot: click613.com/api/eruv/geojson currently serves an older copy.
- Every future eruv change is emailed to you from admin@click613.com, with admin@ in Cc.
